# RESULTS — 实验、数据与方法

> 所有数字来自本机实跑（RTX 5060 Ti 16 GB / i7-14700F / 31.7 GB RAM / Windows / Ollama 0.40.6）。
> 完整数据在本地 `runs/`（不随仓库分发）。

## 1. 指标定义

| 指标 | 定义 |
|---|---|
| **接续率（quote）** | 一条发言是否包含"上一条发言"的中文 6 字连续片段 |
| **回应率（respond）** | 一条发言与上一条共享 ≥4 个中文 bigram（比 quote 宽松） |
| **逐字重复（exact dup）** | 同一 run 内完全相同的发言占比（替换式重写后统计） |
| **改写率** | 被守卫退回重写的发言 / 总发言 |
| 长度 | 每条发言的平均中文字符数 |

> 接续率是"对话连贯性"的**代理指标**，不等于"像人聊天"；本项目尚未做人类主观评分。

## 2. 机制对照（核心结论）

同一话题（"记忆被编辑后你还是你吗"）、同一批 4 个本地模型、各 50 轮：

| 配置 | 接续率 | 回应率 | 逐字重复 | 改写率 | 均长 |
|---|---|---|---|---|---|
| 平行轮转（panel / AutoGen RoundRobin 式） | **2%** | — | 0.5% | 0% | 60 |
| relay，递上一位全句 | 24% | — | 0.0% | 高 | 107 |
| relay，末 100 字 + 90 字上限 | 22% | 58% | 0.5% | 中 | 66 |
| relay，严格引用（`relay_check=quote`） | 34% | 71% | 0.0% | 78% | 78 |
| relay，"回应观点"校验（`respond`） | 11% | 55% | 1.0% | 64% | 77 |
| relay + 结构化摘要（`structured`） | **8%** | 38% | 0.5% | 70% | 70 |

**结论**：

1. 接续几乎完全由"**有没有把上一位的话递过去**"决定：2% → 34–38%。
2. 压缩/摘要会破坏接力：原话是锚点，摘要是噪声。
3. 放松校验能降改写（78%→64%），但接续掉到 11%——不划算。

## 3. 200 轮验收（默认配置）

`configs/tested-4-abliterated-zh.json`，4 域 × 50 轮，主持人每 8 轮，严格引用：

| 指标 | 值 |
|---|---|
| 轮数 / 发言 | 200 / 800（另 645 条修订） |
| 接续率 | **38%** |
| 回应率 | 66% |
| 逐字重复（替换后） | **0.1%** |
| 平均长度 | 76 字 |
| 改写率 | 81% |
| 空回复 / 括号残留 | 0 / 0 |
| 去重触发 | 32 次 / 100 轮 |
| 云端主持人 | 24 次调用，0 失败 |
| 四域接续率 | 33% / 43% / 38% / 38% |
| 墙钟时间 | 33 分钟（4 模型全驻留 GPU，≈10 秒/轮） |

**稳定性**：四段接续率没有随轮数衰减（33→43→38→38），跨域也守住了。

## 4. 模型档位 A/B（50 轮）

| 配置 | 接续率 | 回应率 | 改写率 | 结论 |
|---|---|---|---|---|
| 默认（2B 小陈） | 38% | 66% | 81% | 基线 |
| 小陈 2B → 7B | 41% | 72% | 78% | 小幅收益，慢 20% |

- 收益最大的是**它的下一位**（大刘 24%→40%）：前一位说得越具体，下一位越有东西可接。
- 改写率只降 3pp：说明 ~80% 是"严格引用"的固有成本，不是模型太笨。

## 5. 云端调度成本（可复算）

- 只有 conductor 调云端：每 8 轮 1 次，prompt ≈ 800–1200 tokens，completion ≈ 600–1000 tokens。
- 200 轮实测：24 次调用、约 3 万 tokens。
- 按 DeepSeek 级价格（约 ¥1–2 / 百万 tokens）：**200 轮 ≈ 0.1 元**。
- 1000 轮 ≈ 0.5 元；2000 轮 ≈ 1 元。
- 本地 speaker 的算力成本 = 电费，与 API 无关。

> 对比：4 个 speaker 若都走云 API，200 轮约 800 次调用、每次 1–2k tokens，是几十元级；且并发受限。
> 这就是"云端调度 + 本地演员"的经济学。

## 6. 方法学注意事项

1. **跨批次不可比**：不同话题、不同日的分数差异（±0.7–1.0）和配置差异同量级；比较必须在同批次内做。
2. **改写会替换原版**：统计必须用"每个 (round, sender) 的最新版本"，否则重复计数。
3. **接续率不是质量**：高接续也可能只是"礼貌附和 + 复述"；需要人类评分补充。
4. **样本量**：50 轮单样本的接续率波动约 ±5pp；A/B 的 +3pp 在噪声边缘。
5. **模型行为受对齐影响**：abliterated 模型更愿意聊争议话题，对齐模型会拒答或软化——这是模型差异，
   不是框架差异。
6. **时间/硬件敏感**：并发 speaker 数、`num_ctx`、是否全部驻留 GPU 都会影响延迟与成功率。

## 7. 如何复现

```bash
python supervisor.py --config configs/tested-4-abliterated-zh.json
python tools/relay-analyze.py runs/<id>       # 接续率/回应率/长度
python tools/dup-view.py runs/<id>            # 逐字重复
python tools/phase-continuity.py runs/<id>    # 分域接续率
python tools/summarize-run.py runs/<id>       # 事件计数
```

建议先跑 10 轮冒烟（`rounds: 10`），确认 `utterances` 每轮 +4，再跑 200 轮。
