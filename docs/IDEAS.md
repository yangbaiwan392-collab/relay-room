# IDEAS — 扩展场景与技术路线

> 这份文档记录"这套机制还能用在哪、怎么继续做"，避免后来者重复发明。
> 欢迎认领其中的条目开 Issue / PR。

## 一、扩展使用场景

### 1. 多角色评审 / 需求评审

- 角色：产品经理、工程师、风控、真实用户（四个本地模型，人格化）
- 导演注入：用户访谈原话、竞品事实、历史事故、约束条件
- 接力：每个角色必须先回应上一位的具体点，再补自己的判断
- 产出：比单模型评审更少"都挺好"，更容易暴露冲突
- 需要的改动：conductor 事实源接内部文档；导出结构化评审纪要

### 2. 研究与文献研讨

- 话题：哲学、伦理、政策、医学争议、社会科学
- 导演：每条事实必须标来源（论文/报告），并给反例
- 守卫：检测"空泛同意"，强制每人给一个可检验判断
- 风险：模型可能编造引用；导演应只给"可核查的区间/结论"，并标注不确定性

### 3. 内容创作 / 剧本与小说

- 角色：主角、配角、旁白、编辑
- 导演：剧情节点、设定事实、禁止 OOC 的禁词
- 接力：台词必须接住上一句的情绪/信息
- 需要的改动：把 90 字长度上限放宽；增加"场景状态"黑板（时间、地点、道具）

### 4. 教育 / 模拟法庭 / 谈判训练

- 角色：学生、对方律师、法官、证人（或谈判对手、观察员）
- 导演：注入案例事实、临时改变条件（"现在预算砍半"）
- 价值：接力机制让追问连贯，适合练"追问与回应"
- 需要的改动：人类可随时插话（human-in-the-loop）；评分/复盘输出

### 5. 语言学习 / 多语种陪练

- 角色：不同水平的对话者、纠错者
- 导演：话题 + 目标词汇/语法点
- 改动：语言守卫（必须用目标语言）、纠错回合

### 6. 多模型行为观测台 / 红队

- 固定话题、固定机制，观察 4 个模型的行为差异
- 指标：接续率、复读率、跑题率、附和率、拒答率
- 用途：轻量评测、模型选型、红队探针
- 优点：不需要 judge 模型，成本极低

### 7. 陪伴型本地人格 / 智能家居

- 一个房间内多个本地人格分工：情绪支持、事实查询、提醒
- 延迟敏感：全本地、4–7B、一张卡
- 云端导演只在"内容枯竭"时介入，隐私更好

### 8. 游戏 NPC 群聊 / 剧本杀

- NPC 之间保持连贯对话，导演按剧情注入事件
- 需要的改动：结构化世界状态（地点/物品/关系）；事件触发式导演

### 9. 企业知识圆桌

- 把 conductor 的 fact 替换成 RAG 检索结果 / SQL 查询
- 多模型围绕真实数据接力讨论，减少幻觉
- 需要的改动：检索适配层、来源引用格式、权限控制

### 10. 跨房间 / 多机扩展

- 多个房间共享一个导演；或把 speaker 分布到多台机器（Ollama 远程）
- 需要的改动：bus 换成网络服务（当前是本地 SQLite）；调度与超时策略

## 二、技术路线（按价值排序）

| 优先级 | 方向 | 说明 | 预期收益 |
|---|---|---|---|
| P0 | 降低改写率 | 严格引用对 4B/7B 太难；换 8B+、混合校验（引用或关键词回应）、两次重写 | 改写率 80%→40%，延迟减半 |
| P0 | 人类评估 | 接续率≠像人聊天；需要人工评分与指标校准 | 避免优化错指标 |
| P1 | 自适应导演 | 固定每 N 轮 → 检测重复/饱和才注入 | 云端调用减半，注入更及时 |
| P1 | Web UI | 插话、投票、暂停、换话题、看守卫日志 | 可用性 |
| P1 | 导演 provider 抽象 | OpenAI 兼容 / 本地模型降级 / 规则引擎 | 可移植性、离线可用 |
| P2 | 说话人选择 | 固定轮转 → 按"谁最适合回这句"选人 | 接续质量 |
| P2 | 记忆分层 | 长期偏好/事实库，跨话题复用 | 长跑一致性 |
| P2 | 结构化守卫 | 把"禁句/类比/长度"变成可配置策略包 | 可复用 |
| P3 | 多语言 | 英文/日文提示与守卫 | 受众 |
| P3 | 分布式 | bus 服务化、远程 Ollama | 规模 |

6. 把 `relay_guard` 的阈值（6 字 / 4 个 bigram）做成配置项

8. 给 supervisor 加一个"最大连续改写次数"上限，避免死循环

## 四、已知负结果（别重复踩）

- **结构化摘要接力**：把上一位的话压成"主张/理由/落点"后，接续率从 38% 掉到 8%。
  模型需要原话，不是摘要。
- **放松成"关键词回应"**：改写率降到 64%，但接续率掉到 11%；严格引用才是接续的钥匙。
- **全员禁类比**：指标变好（类比率 47%→3%），但内容变干、变短；建议改成"配额"而不是"全禁"。
- **让模型自己挑开场变体**：它会挑一个当新口头禅；变化应由主管随机指定。
- **把上一位的话全量递过去**：回复越来越长（107 字）；截到末 100 字 + 90 字上限更稳。
